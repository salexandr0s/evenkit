# Navigation controls

Owner: Evenkit. Maturity: pilot. Inventory: E01–E06. Example consumer: the local component catalog. These controls use the existing kit styles and document-level themes.

## Contracts

| Family | Contract |
| --- | --- |
| Tabs | `Tabs`, `TabsList`, `TabsTrigger`, and `TabsContent` preserve Radix props and refs. The root chooses `underline` or `pills`, `sm` or `md`, direction, orientation, and automatic/manual activation. Arrow keys skip disabled triggers. Each panel is named by its trigger. Active tabs use accent text. The underline meets the list baseline, with an inset focus ring that stays inside the scrolling region. Selected pills use a soft accent fill, accent border and small shadow. Selected styling persists during hover and focus. Horizontal panels have 24px separation from their list; vertical panels retain a 16px gap and no top margin. |
| Accordion | `Accordion` preserves Radix's single/multiple value union, controlled/uncontrolled state, direction and disabled behavior. Compose Item → Header → Trigger plus Content. Headers default to h3 and support Radix `asChild` for a different heading level. Trigger icons are decorative. Open triggers have a muted surface; revealed text aligns with the label and leaves room below the chevron. Content opens with a 120ms fade and 2px movement, closes immediately and removes motion under reduced motion. |
| Collapsible | Root/Trigger/Content expose Radix state and refs. It is one disclosure, without adding an accordion heading or selection model. The default trigger includes a decorative rotating chevron. `asChild` preserves the supplied child; a kit Button can supply its own chevron through `endIcon`. Revealed content has an inset rule and the same opening-only motion as Accordion. |
| Breadcrumbs | A named nav contains an ordered list. The last item is the current page. Muted ancestors gain an underline on hover/focus; the current page uses stronger text. All ancestors remain available, long labels wrap and links have 44px minimum height on narrow/coarse-pointer screens. `renderLink` receives native anchor props and a ref so a host router can preserve keyboard, click, and focus behavior. |
| Navbar | A header accepts a linked brand, plain or grouped links, an active ID, account access, a contact action, custom actions, and a router link renderer. Navigation becomes compact below 768px or when the desktop content needs more room. Links and Contact are available in the modal Dialog; the account control stays in the header, and Contact also remains inline when a compact header has room. The menu closes after ordinary link activation. On a resize to desktop it closes and recovers focus to an enabled desktop link, brand, visible action or the header itself; focus on controls that become hidden moves to the visible menu trigger. Disabled destinations have no href and bypass the router renderer. The skip link targets `contentId`; the host supplies a focusable destination. |
| Pagination | The host supplies a one-based `page`, `pageCount`, and `onPageChange`. Inputs are normalized for display; the component never mutates the host page silently. Previous/next and bounded numbered choices use real buttons. Optional `renderPageLink` turns available page choices into host-controlled anchors. Busy/disabled and boundary controls remain disabled. `compact` hides numbered choices and leaves named icon buttons for dense table footers. Compact controls reuse the kit Tooltip on hover/focus, with the same label as their accessible name; scrolling and activation dismiss the hint. Full-text mode retains its visible labels. Page status is announced politely. |

All controls use existing semantic colors, 32/40px control sizes, 44px narrow/coarse-pointer targets, short motion tokens and reduced-motion overrides. Native attributes and event handlers pass through. The parent supplies route destinations, labels, page data and async policy.

Navbar places the brand at the leading edge, primary navigation after it, and account/contact actions at the trailing edge. The current destination uses accent text and a persistent accent rule. Selected dropdown and mobile links also have a soft accent fill; the mobile drawer uses a logical leading rule and a separated navigation group. Pagination gives the current page a filled accent background, contrasting text and stronger weight, uses tabular numerals and keeps compact table controls at their existing density. These selected colours persist during hover and focus. Full pagination groups numbered choices and ellipses into one row, followed by the previous/next group. On narrow screens these occupy separate rows in the same visual and keyboard order; unusually long ranges scroll inside their row with focus-ring space. Directional breadcrumb and pagination icons inherit a private direction variable from the nearest explicit HTML `dir` context, including nested overrides; their CSS does not depend on build-time `:dir()` rewriting.

The primary catalog specimens show editable project details, working disclosures, a website header with local contact/account flows, an application header above the existing sidebar, and changing paginated records. Secondary sections retain manual activation, RTL, unavailable navigation, empty results, busy controls and router examples.

## Public APIs

- `TabsProps` adds `variant?: "underline" | "pills"` and `size?: "sm" | "md"` to Radix Root props. Parts export their corresponding props types.
- `AccordionProps` remains the Radix single/multiple union. Parts export native-compatible props and refs.
- `CollapsibleProps` and its parts retain Radix props and refs.
- `BreadcrumbsProps` accepts `items: readonly BreadcrumbItem[]`, optional `label`, and `renderLink`. Each item has `id`, `label`, and an optional `href` for ancestors.
- `NavbarProps` accepts `brand`, `items`, optional `activeItemId`, `account`, `contact`, `actions`, `renderLink`, `contentId`, navigation/menu labels, and native header props. Each `NavbarItem` has `id`, `label`, `href`, and optional `disabled`. A `NavbarGroup` replaces `href` with `items: readonly NavbarItem[]` for one level of grouped navigation.
- `NavbarBrand` accepts native anchor props and a ref, `children` for the name, an optional decorative `logo`, and an optional `description`. Supply an `href` to the home destination. The existing `brand: ReactNode` slot also accepts a host router link or other custom brand composition.
- `NavbarAction` accepts either `{ label, href, onSelect? }` or `{ label, onSelect }`. `contact` uses this action shape; links remain links and callback actions render as buttons.
- `NavbarAccount` accepts a `NavbarAction` with an optional decorative `icon`, or a menu configuration with `label`, `name`, optional `description`/`icon`, and `items`. The `label` names the account control. Each `NavbarAccountItem` is an action with an `id` and optional `disabled`/`destructive` state. The application supplies account/session state and callbacks.
- `PaginationProps` accepts `page`, `pageCount`, `onPageChange`, optional `compact`, `disabled`, `busy`, `label`, `previousLabel`, `nextLabel`, `pageLabel`, `showStatus`, `statusText`, and `renderPageLink`. `showStatus={false}` delegates announcements to an existing table; `statusText` replaces the default page count during loading or errors. Page link renderers receive native anchor props plus the destination page.

Router renderers must forward the supplied ref, children, native events and ARIA attributes. A renderer must return one focusable link. Supplying a custom renderer does not transfer routing policy to the kit. The Navbar skip link stays clipped and outside pointer hit testing until focused, so an embedded header cannot cover preceding page controls.

Navbar remembers focus owned by its desktop links or mobile trigger while responsive CSS changes visibility. A hidden-control blur restores focus to the visible replacement even when the browser clears activeElement before the resize observer. Moving focus to a host control clears that intent, so resizing does not take focus back.

## Website and application headers

Import `@evenkit/tokens/css` and `@evenkit/ui/css` once in the consuming application. The header uses the active document theme and mode, including its typography, semantic colors, border styles and control sizing. The catalog's Navbar entry includes complete `WebsiteLayout` and `WorkspaceLayout` examples that can be copied into a React application.

The inner header row has a 72px minimum height on desktop and 64px in compact mode. Built-in navigation, account and Contact controls use 44px targets. Brand logos share a 32px frame, and leaf links and group triggers share the same active-route underline. Dropdowns sit below the header with room around its bottom divider and use the kit's elevated surface with 40px rows, increasing to 44px on narrow screens and coarse pointers. Account menus distinguish the user's name from the secondary account description; the account control keeps an accent border and muted surface while its menu is open.

The mobile drawer separates its heading, scrolling navigation and bottom Contact action. Nested destinations have an inset and a quiet leading border beneath their group label. Opening the drawer focuses the active enabled destination, or the first enabled link. The link region scrolls independently on short screens so its last destination and the Contact action remain reachable. Long labels can wrap; the header and drawer use minimum sizes rather than fixed text heights.

Supply a logo to `NavbarBrand` and keep its accessible name in the link text. A decorative SVG, kit icon or image with `alt=""` works when the visible brand name already identifies the destination. Use `description` for a short subtitle. Long names wrap within the available brand area.

Choose stable item IDs and set `activeItemId` from the route. For a grouped destination, use the selected child's ID. Groups open with the existing dropdown primitive on desktop and become labelled link sections in the mobile drawer. Keyboard users can open a desktop group, move between its destinations, activate a link, or dismiss it with Escape. Disabled groups and destinations remain unavailable.

Use `account={{ label: "Sign in", href: "/login" }}` for a login destination, or supply `onSelect` to open your own authentication flow. For an existing session, supply the user's name and account menu actions. The kit renders these controls; the host owns authentication, permissions and session updates. An avatar can replace the default account icon without replacing the control's accessible label.

Use `contact={{ label: "Contact", href: "/contact" }}` for a contact page, or `onSelect` for a host dialog. The label can also be Support or another primary action. In compact mode, the action remains in the header when the header is at least 640px wide and its contents fit naturally. It is also available below the drawer's links. Narrower headers keep the action in the drawer. If a callback opens a controlled dialog, give that dialog a return-focus target that remains visible after it closes. The catalog demonstrates invoker recovery and a mobile menu fallback.

The responsive decision uses the header's available width. A header embedded beside a sidebar can become compact before the browser reaches the mobile breakpoint. Keep custom content in `actions` concise; it remains a general React slot for application-specific controls. Existing consumers using only `brand`, flat `items` and `actions` continue to work.

For an application layout, place `Navbar` immediately above `AdminShell`. Use the Navbar for global destinations and the sidebar for navigation within the workspace. The shell's `header` slot holds the current page context. Point the Navbar's `contentId` at the same content ID passed to the shell. Standalone applications let `AdminShell` render the main landmark; embedded examples use `contentAs="section"` to retain the surrounding page's single main landmark.

Custom `renderLink` implementations receive the supplied anchor props for navigation and href-based account/contact actions. Forward the ref, children, ARIA attributes and native handlers. Preserve modified clicks, download links and non-self targets. `NavbarBrand` is an anchor; a host-specific brand link can instead be supplied through the existing `brand` slot.

The website preview routes between local studio pages, opens a contact form with a local confirmation, and switches between signed-out and signed-in header states. These flows do not send an enquiry or create an account. The application preview has working global destinations, account access and sidebar navigation using fictional records.

The website example's `Header state` selector presets the default header, a selected Work destination, the signed-in account, or an unavailable Journal link. Its value follows the current navigation/account state when those controls are used directly. The width toggle keeps the example and its controls together at a compact width. Use the catalog's theme and mode controls to compare the same state across themes; the original responsive behavior example retains its RTL and unavailable-navigation controls.

## Sources and ownership

Tabs and Navbar derive presentation from the internal `tabs.v1` and `navbar.v1` contracts. Original kit wrappers supply CSS, responsive composition and APIs. Behavior uses pinned MIT-licensed Radix Tabs 1.2.1, Accordion 1.3.1 and Collapsible 1.2.1, with the existing Dialog dependency for mobile navigation. Relevant references: [Tabs](https://www.radix-ui.com/primitives/docs/components/tabs), [Accordion](https://www.radix-ui.com/primitives/docs/components/accordion), [Collapsible](https://www.radix-ui.com/primitives/docs/components/collapsible), and [ARIA breadcrumb pattern](https://www.w3.org/WAI/ARIA/apg/patterns/breadcrumb/).

## Verification

Focused browser journeys cover tab activation and disabled skipping, single/multiple accordion expansion, disclosure state, pagination boundaries, menu dismissal and resize focus recovery, RTL and narrow wrapping. Source and catalog examples receive configured TypeScript/lint checks. Integrated browser and package-consumption results are recorded by the root integration pass.
