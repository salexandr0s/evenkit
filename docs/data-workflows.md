# Data, files, and editable page blocks

25 October 2026. Owner: Evenkit. Maturity: pilot. Catalog consumers use fictional local data. Covers I01–I03, J01–J02, O02, O04 and O11.

## Component contracts

`SemanticTable` and its caption/header/body/footer/row/head/cell parts preserve native table props and refs. Density is a row-height minimum; text wraps instead of hiding content. Column headers use a muted surface, body row headings share their row's background, and the footer has one continuous surface. The caption carries the table's title hierarchy. Numeric cells opt into logical end alignment, tabular figures and unbroken values. `TableScrollRegion` confines deliberate horizontal overflow and accepts a region label and keyboard focus. The host supplies table data, sorting, pagination and empty/loading/error presentation.

`FilterBar` is a real form with host-supplied fields, draft/applied state, apply and reset callbacks, busy state, and a persistent status message. Fields and actions share a row when space permits and wrap independently in narrower containers. Apply uses form submission; while busy it remains focusable with `aria-disabled` and suppresses resubmission. An updating label and decorative spinner remain visible when unapplied edits coexist with a pending result. Reset calls the host and preserves focus. `AppliedFilters` accepts stable IDs, labels and remove/clear callbacks. Its wrapping removal chips show an X beside the label, with the count and clear action in the same group. After the controlled filter list commits a removal, focus returns to the next removal action or the persistent empty status. Deferred host updates are supported; recovery is cancelled when the user moves focus elsewhere. Filter state and result fetching belong to the host.

`FileInput` is a labeled native file input enhanced with a keyboard-operable drop surface. A decorative upload icon sits above the chooser text; constraints remain beside the control. Dragging adds an inset boundary, and invalid selection has a semantic surface and error list. Disabled styling follows the native input, including a disabled ancestor fieldset. It validates each incoming batch against accept tokens, maximum bytes and maximum count, and returns accepted files plus structured rejections. Without `files`, the native input retains the latest accepted batch. Pass a controlled `files` array when keeping a list: it becomes the native FormData selection and picker-cancellation state, so removing a host row also removes its submitted file. The catalog shows this accumulated-list pattern. With multiple selection, `files.length` supplies the existing count unless `existingCount` explicitly includes additional host records. Single-file selection replaces the previous file. The input clears when opening the picker to allow reselection; cancellation restores retained files. Form reset clears errors; a controlled host resets its files array, while uncontrolled selection clears itself. Native required, disabled, multiple, name and form props remain available. The component does not upload or inspect file contents; client checks do not replace server validation. Errors remain associated with the control and are announced. Dragging cannot activate disabled input.

`FileRow` is a list item with filename, type/size metadata, a host-supplied state and progress, and optional open/download/remove/retry/cancel actions. A file icon, content and compact actions form a grid; actions sit beneath the content at narrow widths. Long filenames wrap. Uploading, complete and failed states pair text with a decorative indicator. Uploads reuse `Progress` with a file-specific accessible name: finite values clamp to 0–100, while absent or nonfinite values remain indeterminate. Each icon action retains its file-specific name and tooltip. Hosts own URLs, async operations, cancellation, persistence and focus when a removed row leaves the page.

## Editable source blocks

Copy `registry/blocks/record-workflow.tsx` into a consuming application and adjust the record fields and actions. `RecordWorkflow` receives records and an async `onSave(draft, { signal })` callback. The host returns the saved record and updates the supplied records. Its list filters distinguish editable criteria from the applied query; create/edit opens a stable form with native validation, cancel/reset, dirty dismissal confirmation, pending save, persistent failure and retry. Each save uses an AbortController. Cancel, discard, new editing session and unmount abort pending work; stale results cannot close a newer form. The host must pass the signal through its request and owns persistence, record IDs and any policy for already-committed writes. The catalog supplies a cancellable local save adapter with an explicit simulated failure switch.

The list uses PageHeader for the title, total record count and create action. SearchField keeps the search draft separate from the applied result, and status badges retain plain string table accessors for sorting. Related filters sit together above the table. The catalog puts loading/failure scenario controls after the page; they remain separate from the copied block.

The editor identifies the original record above separate details and notes sections. Its body scrolls independently of the footer, with the shared Dialog fallback for short windows. Reset changes sits after Notes inside the form as a small ghost button with explicit `type="button"`. One persistent SaveStatus region presents idle, dirty, saving, failure and cancellation feedback. On desktop, status sits at the start of the footer and Cancel/Save stay together at the end; errors occupy a full row. On mobile, status sits above an equal-width Cancel/Save pair. The native form ID and external submit control remain connected, and the existing validation, draft and request lifetimes are unchanged.

Copy `registry/blocks/recovery-page.tsx` for 404, unavailable/500, access-denied, offline and maintenance pages. Each state pairs its title with a named decorative icon inside a measured reading width. The host supplies primary and optional secondary recovery actions and can override the title/description and heading level. The catalog's 404 example has one destination; other examples keep a distinct recovery action and a route back to the project list. The block presents the state; it does not infer authentication, network status or server availability.

## Visual and behavior rules

All values use existing `--pk-` tokens and the inherited table/input contract. Controls reuse Button, TextField, TextareaField, Select, Dialog, Progress and Spinner. Page blocks also compose PageHeader, SearchField, Badge, FormSection, SaveStatus and the layout helpers. Tables keep numeric alignment and contained overflow; layouts wrap at narrow widths. Semantic colors support the eight themes and both modes. Logical properties support RTL. Focus rings remain visible; narrow/coarse-pointer actions retain the 44px touch target. Drop surfaces use the fast color-transition token; reduced motion removes those transitions. Progress and activity indicators inherit the shared controls' motion behavior.

Source references are the internal `table.v1`/`input.v1` contracts, the initial LSJ/Alithos/securicheck findings, and Leitspur's file-selection requirements recorded in [the inventory](./component-inventory.md). Implementations here are original kit code. No donor application code or new dependency is included.
